# **🎟️ Coupon Distribution System**

## 요구사항

- 발급 가능 쿠폰은 100개가 있다.
- 쿠폰은 5:3:2의 비율로, 1000원 할인 / 2000원 할인 / 3000원 할인이 가능하다.
- 사용자는 1개의 쿠폰만 발급받을 수 있다.

## 가장 중요한 것

- 정확한 쿠폰의 발급 개수
    - 총 개수
    - 비율 (100개 중 20개 / 30개 / 50개)
- 최대한 빠르게 발급
- 1개의 쿠폰만 발급

## 활용할 것

- **멀티 스레드 환경에서 동시성을 보장해 줄 Redis**
    - 쿠폰 SET 미리 생성
    - 분산 락 시스템을 통한 발급 제어: Redisson
    - 발급 여부 확인 키

## 고려할 것

### 기술적

- Redis 요청에 대해 → 장애 쪽 서술
    - 과도한 요청은 없는가
    - 쿠폰 획득에 대한 영속성 적재가 적절한 시간 안에 이루어지는가
    - 영속성 적재가 실패하지는 않는갸

### 비즈니스적

- 1인당 1개의 쿠폰이 발급되었는가 → Redis 검증
- 쿠폰은 바로 사용할 수 있는가 → DB 영속성

## **주요 컴포넌트**

### **😶‍🌫️ Redis - SET**

- **Coupon Pool (100개 - 50:30:20)**
    - coupon.amount.1000
    - coupon.amount.2000
    - coupon.amount.3000
- **분산 락**
    - lock:coupon:issue:{userId}
- **발급 상태 키**
    - user:coupon:issued:{userId}

### **🌿 Spring 애플리케이션**

**📎Service Layer**

- **CouponService**: 쿠폰 발급
- **CouponLockService**
    - Redisson 락 획득
    - Lua 스크립트 실행: Redis 명령어 다중 실행 원자성 보장

**🔍Domain Layer**

- **User**: 쿠폰 할인 발급 도메인 주체
- **Coupon**: 금액 할인 쿠폰 도메인 객체
- **CouponFactory**: 비율에 따라 쿠폰 종류를 생성 → Redis에 저장

📎**Etc**

- 쿠폰 타입 ENUM -> 1차적으로 진행했으나 동적 변경 가능

### **📊 데이터베이스**

- **User**: 사용자
- **Coupon**: 쿠폰 정보 / 사용 관리 / 사용자 매핑
- **CouponIssue**: 쿠폰 발급 내역

## **쿠폰 발급 프로세스**

### **쿠폰 풀 초기화**

- CouponFactory를 통해 설정된 비율로 총 100개의 쿠폰 생성
- 생성된 쿠폰은 Redis Set(coupon 키)에 저장
- 생성 시점은 이벤트 오픈 전

### **쿠폰 발급**

- 사용자의 발급 요청
- → 기 발급 여부 확인 **(발급 상태 키)**
- → Redisson을 통해 사용자 단위의 락을 획득 **(분산 락)**
- → Lua 스크립트를 실행
    - Coupon Pool에서 쿠폰 pop
    - 쿠폰 발급 상태 저장
- → 할당 쿠폰 / 쿠폰 발급 내역 DB에 저장 (카프카)
- → 락 해제
